## 2026-11-18 - perturbation test design (before any perturbation result)

- S4x shows that rogue beacons differ from legitimate ones in two attacker-side fields: length and received signal strength. A test that changes the length only would miss a model that falls back on signal strength. Three variants:
  - **L**: length and the fields that follow from it (`frame.len`, airtime `wlan_radio.duration`) set to those of a legitimate beacon;
  - **P**: signal strength (`radiotap.dbm_antsignal`, `wlan_radio.signal_dbm`) set to that of a legitimate beacon;
  - **L+P**: both.
- Values are copied from real legitimate beacons of the same attack window (one donor beacon per rogue beacon, drawn with a fixed seed), never invented; all fields changed together come from the same donor.
- Models: the S4 model families, blocked protocol, no training on modified data. Measures: share of rogue beacons still detected, and PR-AUC on beacons, before and after.

## 2026-11-21 - S7 design (before any S7 result)

- Correction to the entry of 2026-11-19: I wrote there that S7 tests "SMOTE before the split". It does not. H4, as registered, compares SMOTE applied to the training folds only with class weighting; synthetic rows never enter a validation or test set. Oversampling before the split, as in Solpan et al. (2026), belongs to the postponed reproduction.
- `scripts/15_s7_smote.py` implements protocol RQ4 with RF and XGB on F-all. Details fixed now:
  - Arms: no treatment (`class_weight=None`, `scale_pos_weight=1`), class weighting, SMOTE (no weighting). The weighting arm is not refitted: it is the S4 runs (in-domain) and the S5 runs (transfer), same code, data, hyperparameters, seeds and training samples.
  - Hyperparameters: those chosen in S4 and S5 for the same block, model and feature set, not tuned again per arm.
  - SMOTE: imbalanced-learn 0.12.4, k = 5, seed = run seed, applied after the -1 fill of the tree pipelines. Only the attack class is oversampled, up to the number of normal rows. Because of the cap of deviation 4 (at most 100,000 normal rows), AWID3 Evil_Twin training sets hold about 45,000-105,000 attack frames, so they are already close to balanced or the attack class is larger; when attack rows >= normal rows, SMOTE adds nothing. The script reports how many SMOTE runs added no synthetic row.
  - ARS: share of the attribution on A fields, on the S4 evaluation sample of each block (seed = block number).
  - Transfer: Evil_Twin only, AWID3 <-> AWID2 on the fields kept in the source, as in S5. The third dataset of protocol 6.3 is not available, so there is no Rogue_AP transfer and no arm with real Rogue AP frames (allowed by RQ4).
  - Decision rule: (i) one-sided Wilcoxon, SMOTE > weighting, on in-domain PR-AUC, 20 pairs (2 models x 2 captures x 5 seeds, mean over the 5 blocks); (ii) dG = G(SMOTE) - G(weighting), 20 pairs (2 models x 2 directions x 5 seeds), 95% bootstrap CI with 2,000 resamples, holds if mean dG >= 0 or the CI includes 0; (iii) as (i) on ARS. If every difference is zero, p = 1. H4 is supported only if p(i) < 0.05, (ii) holds and p(iii) < 0.05; the p-value of H4 for Holm (S8) is max(p(i), p(iii)).
- Known before running, from S4: RF and XGB with weighting already reach PR-AUC 1.000 on every Rogue_AP block and at least 0.9997 on four of the five Evil_Twin blocks (block 3: 0.81 and 0.78). Condition (i) has almost no room, so H4 is unlikely to be supported whatever SMOTE does. I keep the test as registered and will report this ceiling with the result.

The seed-level tests already in this journal are reported in the paper next to the corrected ones; Holm uses the corrected ones.
  - H2b, per capture: PR-AUC part, 5 models x 4 feature sets = 20 pairs; ARS part, LR, DT, RF, XGB x {F-all, F-chatz} = 8 pairs (deviation 8).
  - H4, pooled over captures as designed on 2026-11-21: 2 models x 2 captures = 4 pairs for (i) and (iii); 2 models x 2 directions = 4 values of dG for (ii), bootstrap CI over these 4 values (2,000 resamples), crude with 4 values. With 4 pairs the smallest one-sided exact Wilcoxon p is 1/16 = 0.0625, so (i) and (iii) cannot reach 0.05 and H4 cannot be supported with this unit, whatever the data. I report this as a property of the design.
    - Why not the test blocks as unit (added 2026-11-23): 2 models x 2 captures x 5 blocks would give 20 pairs, but for a given model and capture the five fold models are trained on overlapping data (any two of them share the pre-attack period and the blocks other than their two test blocks), so the per-block results are not independent and a Wilcoxon test on them would give p-values that are too small. This choice comes after the S7 result and does not change the verdict: H4 was already not supported, and condition (i) had no room because of the ceiling noted in the S7 design entry.
  - H3a (32 configurations) and H3b (10 pairs) already use seed-averaged configurations: unchanged.
  - H1c and H2a: the unit is the model family, with the block bootstrap below.
  - H2c stays descriptive (protocol 10). Its tau measures stability to the learner's random state only, and is 1 for XGB by construction; I word it that way.
- **Block bootstrap** (protocol 10; replaces the fold bootstrap of deviation 5). On the seed-0 test predictions (item 4 of the plan). Within each test block, frames in frame.number order are cut into chunks of 1,000 contiguous frames (the last one shorter). A replicate draws, within each block, as many chunks as the block holds, with replacement. Both models of a comparison are scored on the same draw. 2,000 replicates, seed 0; a block draw with no attack frame is redrawn and the number of redraws is reported. 95% CI = percentile interval.
  - Relative drop (H1c: F-all vs F-noFV; H2a: F-all vs F-noA) = 1 - mean over blocks of PR-AUC(reduced set) / mean over blocks of PR-AUC(F-all). One-sided p per family = (1 + number of replicates with drop <= 0) / 2,001.
  - The prediction dump must therefore hold, for seed 0 and all five families: S3 F-all and F-noFV; S4 F-all, F-noA, F-sem and F-chatz, blocked and random; and the mean absolute attribution of every field, for the taxonomy check of 2026-11-15.
- **One p-value per hypothesis.**
  - "At least 3 of 5 families" (H1c, H2a): a family counts only if its point drop reaches the threshold (20% for H1c, 10% for H2a) and its 95% CI excludes 0; otherwise its p is set to 1. Hypothesis p = min(1, 3 x p3), where p3 is the third smallest family p. Reason: under the null at most 2 families have the effect, so a rejection needs at least one of the 3 others to pass, and the union bound gives 3 x p3 whatever the dependence between families. The protocol does not give this rule; I set it after the S3 and S4 counts (1-2 of 5) were known. With fewer than 3 qualifying families p = 1, so the rule cannot turn a failed count into support.
  - Several parts or captures: p = the largest p of the parts (intersection-union test). H1c and H2a: max over the 2 captures. H2b: max over {PR-AUC, ARS} x 2 captures. H3b: max(F-sem part, rule part); the rule part stays exploratory (deviation 9). H4: max(p(i), p(iii)), as registered in the S7 design.
  - H3a: one-sided p = (1 + number of bootstrap rho <= 0) / 2,001, from the clustered bootstrap of S5 (2,000 resamples, clusters = model families, same seed).
  - Wilcoxon: `scipy.stats.wilcoxon` (scipy 1.14.1), zero differences dropped (`zero_method="wilcox"`); the method used (exact or normal) and the number of zero pairs go into the result file. If every difference is zero, p = 1.
- **Holm** over {H1c, H2a, H2b, H3a, H3b, H4}, m = 6, alpha = 0.05. Adjusted p of the k-th smallest = max over j <= k of min(1, (7 - j) x p_(j)). A hypothesis is **supported** only if its adjusted p < 0.05 and every threshold of its registered definition holds (effect thresholds, counts, median ARS >= 0.25 for H2a, condition (ii) for H4). Otherwise it is **not supported**. I do not write "rejected": a failed test does not show the opposite. Where the CI of an effect lies entirely below its registered threshold, I give that CI.
- **Effect sizes** for every test, confirmatory or exploratory: Wilcoxon, matched-pairs rank-biserial correlation (W+ - W-) / (W+ + W-) and the median paired difference with a 95% bootstrap CI over units; ablations, the relative drop with its block-bootstrap CI per family; H3a, rho with its CI; H4 (ii), mean dG with its CI.
- **ARS without U** (protocol 7.1, sensitivity analysis): A share / (S + A + C shares), computed from the family shares stored in S4, S5 and S7. Recomputed for the median-ARS criterion of H2a, the ARS part of H2b, H3a and H4 (iii); reported next to the main values, not in Holm. If no verdict changes, the conclusions do not depend on the U fields; if one changes, I report which one and that it depends on the U fields.
- **Chance-corrected transfer gap Gc** (exploratory). G compares PR-AUCs measured on sets with different prevalences: the whole target for transfer, the attack-window blocks (AWID3) or Tst (AWID2) in-domain. Gc = 1 - k(T) / k(I), with k = (PR-AUC - p) / (1 - p) and p the prevalence of the set on which that PR-AUC is measured; for AWID3 in-domain, k is averaged over blocks with each block's prevalence. With one common prevalence p this is 1 - (T - p) / (I - p). Configurations with an in-domain PR-AUC below 0.5 are left out (k(I) near 0 makes Gc unstable) and counted. Gc is not truncated: above 1 means worse than chance on the target. H3a and H3b keep the registered G.
  - What it checks: whether the S5 transfer failure is an effect of the different prevalences.
  - Outcomes: if every F-all configuration kept has Gc >= 0.9, the failure is not a prevalence effect; if any has Gc < 0.5, G overstated the failure for it, and I report by how much; values in between are reported as they are. The F-sem vs F-all contrast on Gc uses only the pairs left after the exclusion; with fewer than 5 pairs there is no test, only the values.
- **Descriptive, with block-bootstrap CIs:** per-sub-task in-domain results (ET-B, ET-D; protocol 7.2), clean-period false-positive rates, random vs blocked per block.
